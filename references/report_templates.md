# 报告与配置询问模板

所有对话报告必须使用固定标题，不允许自由发挥。配置询问一次只问一项，不把 API 与分批参数合并到同一条消息里；用户已直接提供的参数直接采用，不重复询问。

## 目录

- 配置询问模板
- 配置汇总
- 启动报告
- 续跑报告
- 阶段完成报告
- 输出选择
- 失败报告
- 报告原则

## 配置询问模板

按以下顺序逐项询问，等用户回答后再问下一项；若用户已直接提供某项配置，跳过对应询问，只补缺失项。

```text
【配置 · API 地址】
请提供 OpenAI 兼容的 API 地址，例如 https://api.deepseek.com。
```

```text
【配置 · API 密钥】
请提供 API 密钥。
```

```text
【配置 · 模型名】
请选择或输入模型名。
```

```text
【配置 · PDF 路径】
请提供本地 PDF 文件的完整路径。
```

```text
【配置 · 分批页数】
每批交给模型整理的页数，默认 10，建议不超过 20。
```

```text
【配置 · 并发进程数】
同时调用模型的进程/线程数，默认 4，建议不超过 8。
```

## 配置汇总

收集完六项配置后，先展示汇总并请求确认，再开始任务。

```text
【配置汇总】
- API 地址：<地址>
- 模型：<模型名>
- PDF：<绝对路径>
- 分批页数：<页数>
- 并发进程数：<数值>
请确认后开始，或告诉我需要修改的项。
```

## 启动报告

新任务开始前使用。

```text
【启动报告】
源文件：<PDF 绝对路径>
输出目录：<work 绝对路径>
模型/API：<模型名> @ <API 地址>
运行参数：分批 <页数> 页/批，并发 <数值>
本次计划：提取 → 结构化整理 → 全书分析 → 翻译 → 排版合成 → 错误报告
检测到已有进度：无
本次将执行：完整流程
预计主要产物：<列出本次会生成的文件>
请确认后开始。
```

## 续跑报告

检测到已有进度并准备续跑时使用。

```text
【续跑报告】
进程检查：无残留进程（或已终止 PID <列表>）
目录检查：state.json 正常；runner.lock 不存在（或已清理）
已完成：<已完成的阶段与批次>
待补：<待跑批次、页范围、单元数>
预计工作量：<单元数或批次数>
请确认后继续。
```

## 阶段完成报告

每个阶段完成后使用。

```text
【阶段报告 · <阶段名>】
状态：完成
摘要：<阶段专用摘要>
产物：<绝对路径>
问题：无（或 N 个，简述类型）
下一步：<下一阶段>
请确认：继续下一阶段，或告诉我需要修改的地方。
```

各阶段摘要固定包含：

- 提取：总页数、批次数、空白页数、图像页数。
- 结构化整理：完成批次比例、印刷页码识别情况、空白页数、跨页段落数、失败批次。
- 全书分析：术语表条目数、中心意思条数、`glossary.md` 路径。
- 翻译：单元总数、成功/失败单元数、跨页单元数、[PB] 异常数、partial 文件与正式翻译文件路径。
- 排版合成：成品 PDF 路径、页数、渲染警告数、空白页数；选择 EPUB 时同时给出 EPUB 路径。
- 错误报告：`report.html` 路径、问题总数、按类型分布。

## 输出选择

翻译阶段完成后使用。

```text
【输出选择】
翻译已完成。请选择输出格式：
1. 仅 PDF
2. PDF + EPUB
请回复 1 或 2。
```

## 失败报告

阶段内出现失败时使用。

```text
【阶段报告 · <阶段名> · 失败】
失败对象：<批次/单元/文件>
失败原因：<简要原因>
已保留进度：<partial 或已完成文件路径>
失败日志：<failed_batches.json 或 error.log 路径>
请确认：重跑 / 查看日志 / 调整后重试。
```

## 报告原则

- 每条报告以固定标题开头。
- 产物一律给出绝对路径。
- 问题数量为 0 时也写“无”。
- 不贴大段 JSON 或日志原文。
- 每条报告最后固定用“请确认”收尾。
